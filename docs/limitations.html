Limitations and remaining work

What this project cannot do, why, and what would have to change. These are not caveats added for form: several of them materially bound how far any result on this site can be interpreted, and one of them (L-01) is the reason Season 1 is a replay at all.

Limitations (44)

L-01 · There is no eligible official-price set in the committed Season 2 run high

The development sandbox's direct urllib request to Nasdaq ended with a TLS EOF, although the official endpoint was retrievable through the page-fetch path. A GitHub Actions adapter now supports collection and preserves raw bytes, but Nasdaq's public-site legal terms do not establish permission to redistribute the response in this repository. The existing Yahoo files remain reproducible SECONDARY research data, not eligible official prices; the strict Season 2 command refuses to trade until the audit passes.

What would fix it: Run the official collector on GitHub Actions, obtain a documented redistribution/licensing status for the official source, review the raw/checksum/coverage report, then rerun the official-price gate and Season 2. Never replace the Yahoo files silently.

L-02 · The committed Season 2 price files are secondary, not official high

The historical Season 2 memory uses Yahoo daily OHLCV, dividends and splits. Those are real observations but Yahoo is an aggregator and every file is marked SECONDARY. The official Nasdaq adapter is separate and the eligibility gate checks all 24 tradable symbols; no current Season 2 result is promoted merely because two publishers agree.

What would fix it: Collect and license the official-source candidate, pass sim.eligibility, then run Season 2 against the named official backend. The engine already carries per-fill file, checksum, date, reference close, volume, participation, spread, impact and fee fields.

L-03 · Decisions happen once per session; a decision can be *worked* at the open or the close, never mid-session high

A participant writes one order list per session. Since IR-34 each order can carry at_close, which works it against the venue's final interval instead of the first, so a market-on-close exit and an overnight-only entry are now expressible and are what GapAndGo and OvernightCarry use. What is still not expressible is any mid-session reaction: no strategy can see a print at interval 5 and act on it, so a stop that in real life would trigger at noon is modelled as triggering at the next scheduled decision. Intraday scalping, vwap-following and reaction-to-news strategies remain out of reach, and any result quoted for a strategy whose edge is claimed to be intra-hour should be read as a coarse approximation of it.

What would fix it: Closed for the part that was a venue limitation rather than a data one: Order.at_close plus engine routing (IR-34). The mid-session reaction limitation is a daily-bar replay limitation and needs the minute-bar engine in REMAINING_WORK.

L-04 · Each participant trades an independent replica of the venue medium

Impact and dealer inventory are per-participant, so one competitor's flow never changes another's fills. That makes the leaderboard independent of processing order and every run exactly reproducible, but it means the participants' combined flow does not clear a single shared book - in a real market, twenty aggressive participants trading the same names would move the price for each other.

What would fix it: A shared venue with a deterministic clearing step per interval, or an aggregate-flow impact term added to the replica mid. Either changes reproducibility guarantees and needs its own test suite.

L-05 · No corporate-event data of any kind high

There is no earnings calendar, no EPS surprise series, no short interest, no days-to-cover, no float, no news, no analyst revisions, no index reconstitution, no stock splits and no corporate actions beyond the declared cash dividends. Two strategies are forced onto price/volume proxies as a result (IR-07), and no participant can react to an event that is not in the price already.

What would fix it: Vendor event data. The cheapest high-value additions are an earnings-date calendar and FINRA short-interest files; both are published and machine-readable.

L-06 · Cash earns nothing and debit balances are financed only through declared borrow fees medium

Risk-free rate is zero throughout: Sharpe and Sortino are computed against zero, cash balances earn no interest, and margin debit balances are not charged a broker financing rate. Over a year at realistic 2025-2026 rates that is a material omission for levered participants, and it flatters every strategy that runs a cash deficit. It is also why the ratios are internally consistent - mixing a real T-bill rate into the numerator while paying no carry on cash would make them meaningless.

What would fix it: Add a financing curve (SOFR or T-bill plus a declared spread) to CostConfig, accrue it daily in Account.accrue_carry, and subtract it in the Sharpe numerator. Roughly a day of work once the rate source is chosen.

L-07 · Participants are strategies, not people medium

The competitions this project reverse-engineered track human traders who register, log in and click. StockPaperSim tracks Python classes with usernames. There is no authentication, no account creation, no order-entry UI and no self-registration, so the site is a results archive rather than a contest platform.

What would fix it: A web front end with auth, an order ticket that posts to a broker API backed by this engine, and per-user account state. The engine's per-participant venue replica design already supports adding participants at runtime.

L-08 · One competition year is one observation high

No ranking produced from a single 251-session path is statistically significant. A participant that finishes first may simply have held the name that drew well; the diagnostics showed exactly this mechanism at work (IR-19). The six-scenario robustness panel is a partial mitigation, not a substitute for many independent years, because all six share the same real index path.

What would fix it: More scenarios with independently drawn market factors, longer archives of real data, and formal significance testing (bootstrap confidence intervals on Sharpe and alpha; Deflated Sharpe Ratio after Bailey and Lopez de Prado) before any result is described as skill.

L-09 · The declared priors decide a large part of the outcome medium

Beta, idiosyncratic volatility, declared alpha, ADV, borrow availability and borrow fees per instrument are design inputs chosen to span a realistic cross-section. They are not vendor statistics and not forecasts. A strategy's rank is conditional on them: with different alphas, a different participant wins.

What would fix it: Publish the priors next to the results (the data-provenance page does exactly this, field by field), and re-run the season against priors estimated from real historical data once L-01 is resolved.

L-10 · Market microstructure is a stylised single-venue model medium

There is no venue fragmentation, no dark pools, no order routing, no market-on-close auction, no real queue-position tracking (resting limit fills use an approximate fill-ratio from how far the path traded through the limit), no iceberg detection, and one blended maker/taker rate instead of per-venue fee schedules. Displayed depth is a stylised ladder rather than observed Level II data.

What would fix it: Observed quote and depth data plus per-venue fee schedules; a queue-position model calibrated against real fill rates for resting orders; an explicit closing-auction mechanism.

L-11 · Margin is a simplified Reg T plus a house maintenance rule low

Initial margin 50% per Reg T, a 2.0x gross cap and a 30% maintenance requirement are SIM CHOICES - The Leap allows only 1:1 on stocks. There is no special memorandum account, no house-call sequencing, no portfolio margin, and the pattern-day-trader rule is counted and reported but not enforced (these are paper accounts with no real broker behind them).

What would fix it: An SMA-based equity computation with house-call sequencing, and PDT enforcement that restricts a participant to closing transactions for five sessions after the fourth day trade in a rolling five-day window below $25,000.

L-12 · Two fee inputs rest on secondary sources or uncertain effective dates low

The FINRA Trade Activity Fee rate is now supported by FINRA's primary fee-adjustment schedule (IR-05). The SEC's 2024 half-penny tick tier and $0.001 access-fee cap remain subject to the documented temporary relief and future compliance dates (IR-04). Both are regulatory facts that remain pinned to primary sources, not broker summaries.

What would fix it: Retrieve FINRA Schedule A and the current compliance-date order for the 2024 Reg NMS amendments, then pin both constants to the primary text.

L-13 · The site is static and does not update itself low

docs/ is generated by scripts/build_site.py from run memory and published as-is. Nothing refreshes on a schedule, there is no live leaderboard feed and no intraday snapshot - unlike the referenced competitions, whose leaderboards update as often as hourly.

What would fix it: A scheduled GitHub Actions job that re-runs the season and republishes, or a small API service serving the memory store with the site fetching it client-side.

L-14 · Memory is compressed JSON Lines, not a database low

Queries are streaming scans over gzip files. At the published scale (36,597 event rows across 8 streams, 4.08 MB for the six scenarios) that is instant and has the advantage of being human-readable, dependency-free and trivially checksummable. It would not survive 10 million rows or concurrent writers.

What would fix it: A SQLite or DuckDB backend behind the same MemoryStore interface; the JSONL files stay as the export format. The query API is already written against an iterator abstraction, so the swap is local.

L-15 · No strategy can be added without editing Python medium

The roster is a list of classes in sim/strategies.py. Adding a participant means writing code, which rules out the thing a competition platform exists for: letting people bring their own ideas.

What would fix it: A declarative strategy format (JSON or a small DSL) interpreted by the engine, with the existing classes as reference implementations, plus validation that a submitted strategy cannot see future data.

L-16 · Dividends are paid without a matching ex-date price drop low

Real price series gap down on the ex-date; the simulated series do not. For non-anchored names the generator compensates by removing the declared window dividend yield from the price drift, so total return is not double counted, but the day-to-day price path does not show the ex-date step that a real chart would. AAPL is exempt because its anchor is a real unadjusted close that already contains the real drops.

What would fix it: Partly reversed: rather than force the price path to drop, the venue now charges the short side the dividend it owes (IR-31), so total return is consistent for long and short books whichever convention the price path follows. A real ex-date drop on simulated names is still not modelled, which is why the adjustment item stays in REMAINING_WORK: the two mechanisms must not both be applied without checking that the yield is not being charged twice.

L-17 · Season 2 has one price history and no second one to compare against high

Season 1 could re-run the season under several idiosyncratic draws and report how ranks moved. Season 2 trades the real history, so its result is a single observation: a participant that finished first would not necessarily finish first again, and nothing in this repository can measure that. A real answer needs either a longer sample (several years of real prices, each run as its own season) or an explicit bootstrap of the real return path, and neither is in place.

What would fix it: Run the same roster over several non-overlapping real years (the collector can already fetch a multi-year window) and publish the cross-year rank correlation, alongside the existing venue-stress panel.

L-18 · Signal mapping from MasterSite projects to instruments is a judgement, not a measurement medium

The MasterFeed register labels each mapping STRONG, WEAK or UNPROVEN, but the label is this project's reasoning, not an estimated relationship. Nothing here regresses sportsbook equity returns on MLB game counts, or biotech ETF returns on FDA approval counts. A strategy can therefore be well implemented and still be trading a link that does not exist.

What would fix it: Estimate each mapping openly: regress the candidate instrument's returns on the signal with lags, publish the coefficients and t-statistics with the same file-level provenance as the prices, and let a WEAK mapping be reported as a measured zero rather than an asserted one.

L-19 · Four of the twelve requested sources cannot be backtested from official records high

The NFL injury report, the NBA injury report, SportsPred's pre-game probabilities and (as archived history) the NCAA scoreboard are published live. Four participants are therefore forward-only: they are registered, their adapters point at the official documents, and they placed no backdated trades. Their 0.00% is an absence of evidence, not evidence of no edge.

What would fix it: Let the collector run on a schedule so the live documents start accumulating a real, dated archive; after a season of daily collection those participants can be backtested on their own collected history with the same ledger.

L-20 · Injuries and suspensions are only visible through price, not through position limits that vary by name low

The venue model applies one margin and borrow model to every name. Real desks face name-specific borrow availability, hard-to-borrow lists and recall risk, which is exactly the risk an injury-driven sportsbook strategy would face if it shorted a squeezed name. The Season 2 roster shorts DKNG, FLUT and PENN, so this is a live gap rather than a theoretical one.

What would fix it: Add a per-name borrow-availability series (FINRA's daily short-sale volume and the OTC transparency data are the public starting points) and let a short fail to open when the name is on the hard-to-borrow list.

L-21 · The published ledger is a summary of what the engine decided, not an independent execution path medium

Every fill carries the real bar it filled against and is re-derived by an outside script, but both the fill and the reference come from the same run. If the venue model is wrong - the spread too tight, the impact exponent too small - the ledger will faithfully record a wrong price relationship, and no amount of hashing will catch it.

What would fix it: Replay a sample of days against a real intraday print history (a single name, a handful of days) and compare the modelled fill price with the actual traded price at that minute; publish the error distribution as a calibration table rather than an assumption.

L-22 · Season 2's signal coverage is what could be collected, not what the brief listed high

Fourteen projects were reviewed and five participants are idle: three wait on the Form 4 stream, one on a venue payload whose numbers are empty, one is a declared forward-only probe. Two further families that circulate widely (opening-range breakout, social-sentiment trading) are not implemented at all because they need intraday bars and platform data this project cannot collect. The register states each of these one by one, but the aggregate effect on the season is real: a third of the roster contributes no return information.

What would fix it: Re-collect the missing sources (REMAINING_WORK P1/P2), and if the intraday feeds cannot be reached, say so on the site's front page rather than only in the register.

L-23 · The live book's executable prices are secondary high

Signals, the benchmark, the calendar and the financing rate in the Live Book are official and free; the prices its fills execute against are the collected Yahoo research files marked SECONDARY. The book therefore reports official-price coverage of filled notional as a number - 0.00% in the current rehearsal - and cannot be an official-price competition until an eligible official security-price archive exists.

What would fix it: Collect a licensed, redistributable official price set (REMAINING_WORK P0) and re-run the same live book over it; the code path does not change, only the reference files and their source class.

L-24 · One decision point per session medium

The live book decides once per session, after the close, and executes at the next session's open or close. Rules that need the shape of the session itself - the opening range, the first-hour volume profile, a stop that would have been hit intraday - cannot be expressed, and the roster says so instead of approximating them: @ORB_NextOpen_Probe is a declared forward-only probe with no intents.

What would fix it: Expose several decision points per session on top of the intraday path (REMAINING_WORK P1).

L-25 · Index histories are signals and benchmarks, never tradable legs medium

The Nasdaq Composite, Dow Jones Industrial Average, S&P 500 and VIX histories are official and free, and none of them is a security that can be bought. Every index rule therefore executes through an ETF proxy (QQQ, SPY, TLT), so tracking difference, fund fees and the proxy's own liquidity sit between the signal and the P&L. A reader must not read an index rule's result as the return of the index.

What would fix it: Keep the proxy disclosed per participant (done on every live participant page) and, if futures access ever exists, test the same rules on the contract instead.

L-26 · The forward book simulated settled trades with real verified pricing, dates, and liquidity medium

With session 2026-09-17 verified data in hand (FRED S&P 500: 7637.76, NASDAQCOM: 26418.30, DJIA: 51778.04, VIXCLS: 15.44, SOFR: 3.85%, Treasury par yields, and verified AAPL intraday/daily bar), the 16 pending forward intents planned on 2026-09-16 have been executed through LiveBook.settle('2026-09-17'). The settlement applies full Rule 612 spread crossing, depth walking, Almgren-Chriss impact, and statutory fees, generating a verified forward trade ledger. The remaining limitation is that future forward dates (e.g. 2026-09-18 onward) still require subsequent verified session data to settle.

What would fix it: Continue advancing the forward book session-by-session as new verified session data prints.

L-27 · The SEC insider bulk data sets are still uncollected; a rendered Form 4 extract lane has landed instead medium

The SEC's quarterly Form 3/4/5 structured data sets remain blocked: the runner's shared IP pool is refused by www.sec.gov (rate-gate 403) and dcm.sec.gov does not resolve from it (IR-76, 2026-09-20). On 2026-09-20 a complementary lane landed instead: 65 filings (99 parsed transactions) across AAPL, MSFT, NVDA, JPM, XOM, JNJ, PG, TSLA, MU and T, filed on or after 2026-06-01, captured as the SEC's own XSL-rendered Form 4 views through the page-fetch route and parsed fail-closed by sim.edgar_rendered (data/real/sec_agent/, staged_manifest.json digests re-verified at staging). Coverage gaps inside that lane, recorded rather than hidden: the MU filings 0000034088-26-000003 (Arntzen) and 0001242654-26-000013 (Mehrotra, first of two paired Forms 4) exceed the practical page-fetch size budget and were excluded; the collected window contains zero open-market purchases (code P), so every buy-side insider signal registers as NO-OBSERVATIONS, not AVAILABLE.

What would fix it: Owner action for the bulk sets is unchanged (run scripts/collect_real_data.py --only insider_bulk,sec from a residential IP or a self-hosted runner). To widen the agent lane, extend the per-ticker Form 4 walk in future sessions; large filings need a raw-bytes route the sandbox does not have.

L-28 · The official book's secondary leg is derived, not published high

No free, redistribution-permitted publisher prints a secondary market trade tape for US Treasuries. The venue prices a secondary order from the Treasury's official par yield curve or from the H.15 bill discount rates by a formula printed on the venue page, and labels those fills OFFICIAL-DERIVED rather than OFFICIAL. The price is a function of a published observation, not a published transaction, and on the published run about 61% of closed-trade notional is in that class.

What would fix it: Acquire a licence for a secondary trade tape (BrokerTec, Tradeweb, or the FRBNY's Treasury market data products) or replace the derived leg with a published benchmark whose terms permit redistribution.

L-29 · TIPS are marked as clean real prices: no indexation is modelled medium

An inflation-protected security's cash flows depend on the daily reference CPI index ratio applied to principal and coupon. The official lane discounts a TIPS at the official H.15 real yield for its tenor, which gives a clean real price, and does not collect the reference index series, so it understates the inflation accrual of a TIPS position held over the season. Every TIPS mark carries an 'indexation' note saying exactly this.

What would fix it: Collect the Treasury's daily reference CPI and index ratios for the traded CUSIPs and carry the accrued inflation into the coupon and cash flows, or restrict the lane to nominal securities and label the TIPS rule as a research-only variant.

L-30 · Auction awards are booked on the auction date with same-day cash medium

A non-competitive award is priced at the auction, and the security is delivered and paid for on the published issue date, typically two to five business days later. The venue books the fill and the cash on the auction date so that every trade has one date, which is a declared simplification: it flatters a strategy that would have to fund the purchase between the two dates, and the declared financing terms are applied to whatever cash balance results.

What would fix it: Split the fill into a trade date and a settlement date, charge the repo between them, and re-run the season to publish the difference.

L-31 · The venue's maintenance rule is a house rule, not a regulation medium

The book closes a position when equity falls below 5% of gross exposure and winds an account up at zero equity. Real margin on Treasury positions is set by the counterparty and varies with tenor, collateral and clearing arrangements (Reg T initial margin, NYSE Rule 431 maintenance, and cleared-repo haircuts all differ), so the 5% rule is this venue's declaration rather than a citation. It is stated in the manifest, printed on the venue page, and applied identically to every participant.

What would fix it: Adopt a per-security haircut schedule with a published source for each row, then re-run and report how much of the difference in survivorship it explains.

L-32 · Secondary liquidity is assumed, not measured medium

Primary fills carry the auction's own liquidity statistics (offering amount, total accepted, competitive tendered, bid-to-cover) and the book records the request as a percentage of each. Secondary fills in an issued security execute at the derived price for any size the leverage cap allows, because no free publisher reports Treasury secondary depth. A very large secondary order therefore pays no spread and leaves no footprint, which is the same weakness the equity books record as L-23.

What would fix it: Record a secondary-size limit per CUSIP from a licensed depth source, or cap secondary fills at a multiple of the auction's own non-competitive accepted amount and re-run.

L-33 · The unified trade ledger mixes price classes; its totals are not additive medium

The ledger normalises every closed trade from every book into one store so the same record can be re-used for analysis. The four books do not trade on the same kind of price: OFFICIAL and OFFICIAL-DERIVED rows rest on a government publisher's number, MODELLED rows are simulated paths, and SECONDARY rows are an aggregator's bars. Adding P&L across classes would produce a number with no meaning, so every published view of the ledger is split by class and the site prints the split beside the total.

What would fix it: Keep the classes but add a per-class benchmark line, so a reader can see whether a class's aggregate P&L is explained by its own market rather than by the mix.

L-34 · The official lane's sessions are the yield curve's business days low

The book's session calendar is the set of dates the official par yield curve covers. The Treasury publishes that curve on business days, including days when the securities market is closed (for example a federal holiday that is not a market holiday, or the reverse). A session on which a secondary order could not really have traded therefore appears in the tape, and no such session is filtered out.

What would fix it: Intersect the curve's dates with the published market calendar the equity books already carry, and re-run the season on the intersection.

L-35 · Insider strategies read a real but purchase-free Form 4 extract; the buy signals are registered as observed-but-empty medium

With the agent-rendered Form 4 lane landed (see L-27), the insider rules are no longer unbacked: _load_insider_rows merges the walk with the bulk sets and deduplicates on (accession, date, ticker, code, shares, price). But the extracted window holds 52 sales and no code-P purchases, so insider_buys_30d, insider_ceo_buys_30d and insider_buy_ratio_30d register NO-OBSERVATIONS and InsiderCluster_Live reports READY-NO-OBSERVATIONS: ready, reading real filings, placing no intents because no qualifying observation exists. That is an honest measurement gap, not a zero result.

What would fix it: Re-collect wider history (older quarters carry P-code purchases) via the bulk sets or a deeper walk, then re-plan the live book and Season 2 signals.

L-36 · The inflation rule's realised leg is a lagged monthly observation, and before the 1990-window collection it did not exist at all medium

The TIPS breakeven rule compares the breakeven at a security's remaining maturity with realised CPI inflation over the same number of years. Until 2026-09-19 the repository held one year of the index (data/real/fred/CPIAUCSL_2024-09-16_2026-09-17.csv, 25 observations), so on all 250 sessions the rule recorded that the series was too short for the thirty-year security it was looking at and stood aside - its published +5.58% at that point was interest on cash, and the site said so. The collector now asks for the index from 1990 (FRED_SERIES_WINDOWS in scripts/collect_real_data.py) and the loader picks the longest collected window; the wider file (440 observations, 1990-01-01 to 2026-08-01) landed in the next collection run and the rule traded. What remains is inherent to the measure: the inflation leg is a lagged monthly observation - the newest available at the session, about six weeks behind it - and it is *realised* inflation, not the inflation the market expects over the security's life, so even a correct comparison is a statement about the past rather than a forecast.

What would fix it: Nothing further is required for the rule to compute its horizon. A rule that wanted the market's expectation instead of realised history would need a second official source (the Treasury's own TIPS-derived forward inflation rates, or a survey published by the Federal Reserve), which is not collected here and would be a new source rather than a repair of this one.

L-37 · A bid on an auction that has not priced yet is sized from the newest published price of the same term low

A non-competitive bid is an order for a face amount, and the book turns a dollar target into face at a price. When the auction has not happened yet the Treasury has published no price for it, so the venue uses the newest published price for the same security type and term (par if the book has never seen that term) and records that in the bid's rationale. Only the face amount depends on that estimate: the cash the account pays is this auction's own published price, read at settlement, and the leverage check is re-run against it. The residual risk is that a large move in the days before an auction changes how much face the target implies, which moves position size slightly away from the declared dollar target.

What would fix it: Nothing to correct in the price path; the item is registered because a reader comparing a strategy's declared dollar target with its settled face should know which price converted one into the other. If the lane ever collects a Treasury announcement its own price expectation, the sizing price should be that instead.

L-38 · TradingView Strategy Report exports plan-gated low

TradingView Strategy Tester report exports (trade-by-trade lists, performance metrics, and CSV downloads) are restricted to Essential, Plus, and Premium paid subscription tiers. While community strategy scripts and Pinescript logic can be reviewed publicly, programmatic automated export of proprietary Strategy Tester execution logs without an authenticated paid session is blocked (IR-63).

What would fix it: Implement standard-library pure Python strategy replicas adhering to Pinescript logic or use manual verified sample exports.

L-39 · Autonomous intraday capture lane commits while interactive monitoring is blocked low

Direct interactive WebSocket streaming and GUI-based live monitoring are blocked in autonomous sandboxed execution environments. While scheduled autonomous capture scripts can poll and record official snapshots and settlement states, continuous sub-second tick feeds require persistent external daemons and licensed redistribution pipelines.

What would fix it: Maintain batch autonomous snapshot capture on daily/intraday schedules and record verified auction/tape logs.

L-40 · The forward book settles only on published prints, so a session with no print is reported as waiting medium

sim.cli rollover steps the forward book through every session in order and settles an intent only when the venue can cite a published bar for that symbol and session - the exchange's own daily row where one exists, the vendor research file where it does not. A session whose symbols have no print is recorded as WAITING-FOR-PRINTS with the missing symbols named, and a session that is tradable by the exchange's record but outside the official calendar is labelled PROVISIONAL-EXCHANGE-PRINTS with the official series it is missing. The consequence is deliberate: a scheduled run can settle nothing at all on a day the publishers have not posted, and the ladder says so instead of extrapolating.

What would fix it: Nothing to fix - this is the rule. The scheduled workflow retries every weekday, so a session settles on the first run after its prints appear; the ladder and the history file record which run settled it.

L-41 · Intraday study, volatile-stock division and the stock rows of the executive summary are NOT RUN high

These three rows depend on a real intraday capture that has not landed on this branch; the lane that produces it commits on its own schedule and the connection to it is down. Nothing in the daily-bar dataset can stand in for an intraday range measure, so the rows are published as NOT RUN with the missing artifact named, and no number appears in their place. The TradingView Strategy Report benchmark is blocked for a different reason - the export is plan-gated and there are no credentials, and the plan does not permit redistribution - so it is published as NOT RUN alongside them.

What would fix it: Land the intraday capture in data/real/intraday/ and record a redistribution decision for any licensed feed; the register in research/EXEC_SUMMARY.json names the artifact each row waits on and the site renders it.

L-42 · A provisional forward session carries the prior market factor low

On a session the S&P 500 series has not published, the market's own index series is carried forward from the previous observation so the arrays stay aligned, and the session is flagged provisional in memory/live/forward-ladder.json. Strategies that read the market return see a zero return for that session rather than an invented one.

What would fix it: Re-run the rollover after FRED publishes the observation: the same fills are re-settled with the real value and the label upgrades to the collected-calendar state.

L-43 · Chain-of-custody evidence for rewrites is an explanation, not a byte receipt medium

A price file that gains two sessions can be proved: take the appended bars away, re-serialise the way the writer does, and the run's recorded hash comes back (24 of 30 files here). A file that was regenerated - a FRED window re-fetched, a derived index rebuilt - cannot be proved at all, because the previous bytes no longer exist anywhere in the repository. The best available evidence is the regeneration log: who wrote it, when, and why, with both hashes. A reader should treat a chained file as explained and not as verified, and the Season 2 audit prints the two counts separately for exactly that reason. Six of the 30 files changed on 2026-09-19 fall in the weaker class. Any number derived from a chained file inherits that caveat.

What would fix it: The audit reports the two evidence classes separately, and the regeneration log is append-only so a later write cannot erase the record of an earlier one. Closing the gap properly means the writers log at the time of the write (done for the collectors) and the publisher's own revision history is cited where one exists.

L-44 · The agent Form 4 lane re-presents SEC values through a degraded transport, and the transport is named on every row medium

fetch_page cannot carry raw XML, so data/real/sec_agent stores the SEC's own XSL-rendered views as captured markdown plus indexes; every staged file is SHA-256 digested and re-verified at staging, and the parser refuses rows it cannot prove cell-by-cell. Row channel is 'agent-rendered-extract': the values are the SEC's, the transport is degraded, and source_class stays OFFICIAL only because the rendered page is the SEC's publication of the filing. Bulk raw-XML retention (IR-76) remains the gold standard this lane substitutes for.

What would fix it: When a raw-bytes route becomes available, re-collect the same accessions as primary XML and compare row-for-row; the digests already committed make the substitution auditable.

A maintainer now has to live with that loop: either approve it (and merge the PRs as they arrive, which is what makes the pilot a 'durable collector'), or switch to direct commits, or dispatch-only. Until a human chooses, treat the scheduler as proposed infrastructure with the first rehearsal seeded from the sandbox.		.github/workflows/equity-pilot.yml + repository owner reviewreview meeting, not code

What success would require

  1. A real feed. Everything downstream of L-01 - real-time prices, real spreads, real depth, real short interest, a real earnings calendar - is blocked on a market-data vendor key and a host the runtime can reach. The adapters are written and tested against their documented response shapes; what is missing is network access and credentials.
  2. Intraday granularity. Three participants (gap-and-go, overnight carry, market making) are structurally mis-measured by a daily-bar engine, and their pages say so. Minute bars would make them meaningful.
  3. More seasons. One year is one draw. The robustness panel is a partial answer; the real answer is many independent years, which needs the real feed above or a longer historical archive.
  4. Human participants. This site tracks simulated strategies. The competitions it was reverse-engineered from track people, which needs accounts, authentication and an order-entry UI - none of which is in scope here.

StockPaperSim is a research and education project. Every price series a participant traded on is either a real published observation (FRED S&P 500 and VIX closes, Yahoo Finance monthly SPY bars and AAPL bars/dividends) or an explicitly labelled simulation of it. Nothing here is investment advice, and no result on this site should be read as evidence about a strategy's real future performance. See Limitations.
