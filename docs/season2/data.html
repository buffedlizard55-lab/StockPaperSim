What is collected, what is modelled

Collected observations and source classes

  • Prices and volumes for every traded symbol: the current committed research run reads collected vendor daily bars under data/real/prices/yahoo/, each file hashed and listed below. Yahoo is an aggregator, so its class is SECONDARY. The official Nasdaq adapter writes separate normalized files plus raw responses under data/real/, but the strict gate also requires explicit redistribution permission.
  • The market and volatility path: FRED SP500 and VIXCLS daily closes, i.e. the official reserve-bank series.
  • The calendar: FRED's observation dates, so holidays are the observed exchange dates rather than a hand-typed list.
  • The events: SEC EDGAR Form 4 filings, openFDA decisions, the official MLB schedule feed, NOAA/NCEI daily summaries, FRED yields and the Kalshi settled-market list, each with the endpoint recorded.

Modelled (declared, and stress-tested)

  • The intraday path inside each collected daily bar: the open/high/low/close and volume are observed fields, but the sequence of prices between them is not observable from daily data.
  • The venue: quoted spread, displayed depth, impact, participation cap, borrow fees and market-maker behaviour, all as declared in sim/config.py and registered as IR-40 to IR-46.
  • Dividend treatment is only applied when the selected source records an event; the current Yahoo research run uses a secondary event feed, while the official adapter records a separate dividend endpoint and refuses incomplete status in the strict audit.

Not retrieved

  • Consolidated-tape intraday history, which would be the only way to make the intraday path observed. No free, redistributable tape exists.
  • An archived NFL/NBA injury series and pre-game model snapshots: those documents are published live, so the strategies that read them run forward-only.
