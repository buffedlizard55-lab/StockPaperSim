What could not be backtested, and why

  • Injury feeds (NFL, NBA). Both leagues publish live injury documents, not a retrievable archive of past seasons. The documents were fetched, hashed and stored; the strategies are forward-only and place no backdated trades.
  • SportsPred. The project emits pre-game probabilities with no archived timestamped snapshots, so a backtest would require recomputing the model here — that would be this repository's model, not the project's.
  • NCAA scoreboard. The official NCAA endpoint was probed and stored; the archived season is not enumerable from it in a bounded number of requests, so its rule runs forward on the same attention hypothesis as the MLB participants.
  • Kalshi. The venue's own settled-market list was collected, but every numeric field (volume, open interest, last price) came back null, so the attention signal cannot be computed from it. The participant is therefore reported as data missing rather than given a made-up value: insider_buys_30d.
  • "CEO". No project named CEO exists in the directory (checked against the official GitHub API, 39 public repositories). The CEO idea is implemented on the filing that records CEO behaviour: SEC Form 4, filtered on the officer title.

Season 2 trades real, collected daily prices (Yahoo Finance chart API files under data/real/prices/, cross-checked against the Nasdaq quote API and the Federal Reserve Bank of St. Louis' SP500 series) and real dated events (SEC EDGAR Form 4, FDA openFDA, MLB StatsAPI, NOAA/NCEI, FRED, Kalshi). The intraday path inside each real daily bar is still modelled, the venue is still modelled, and dividends come from a vendor event feed rather than the issuer - all three are declared in the irregularity register and on the data custody page. Nothing here is investment advice.
